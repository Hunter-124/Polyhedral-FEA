## What it is

A compact multi-head MLP that predicts the outcome of a candidate meshing
action for a given CAD part and load case, so that a chooser can rank actions
before any of them is run.

| | |
|---|---|
| Inputs | 58 standardized columns: 26 campaign geometry/BC features, 15 offline CAD descriptors, 7 case columns, 8 action columns, 2 categorical indices |
| Outputs | 7 regression heads (`rel_err`, `rel_err_rel`, `geo_chamfer`, `geo_p99`, `dof`, `mesh_ms`, `solve_ms`), 1 feasibility logit, 1 policy vector of width 7 |
| Trunk | `Linear -> GELU -> Linear -> GELU`, width 96, with 4-dim embeddings for `order_idx` and `mesher_idx` |
| Export | ONNX opset 17, single-threaded CPU, deterministic |
| Runtime | ONNX Runtime via the C API, no Python at inference |

All regression targets are `log10`. `rel_err_rel` is `log10(rel_err)` minus that
case's median over the actions actually run: the absolute level of `rel_err` is
set largely by the quality of that case's reference, which a held-out part never
shows the model, while the *ordering* of actions within a case survives the
centring and is all a chooser needs.

## Intended use

Propose a starting mesh configuration for a linear-elastostatic solve on a CAD
solid, inside PolyMesh, where the downstream estimator, health gates and
resource guards all still run. **The advisor proposes; the estimator disposes**
(ADR-0027 §8).

## Out-of-scope use

- Any part unlike the training corpus. See *Limitations*: the corpus is eight
  procedural families, and on an unseen family the regression heads can be
  numerically meaningless.
- Non-structural physics, non-linear material, contact, dynamics.
- As a substitute for the solver, the error estimator, or the health gates.
- Reporting `predicted_*` values to a user as if they were estimates. On an
  unseen family they are not; see *Known failure modes*.

## How the decision is made

Three choosers exist and they are **not** equivalent. This distinction was the
single most consequential finding of the evaluation work.

| chooser | rule | status |
|---|---|---|
| `advisor_policy` | one forward pass at the default action, read the policy head, clamp and argmax | **what shipped historically** |
| `advisor_argmin` | enumerate the measured candidate grid, argmin the predicted outcome | reported in every historical regret number |
| `advisor_gated` | filter candidates by predicted failure probability, then argmin over survivors | **what we now ship** |

Measured leave-one-family-out at a median DOF budget, `rel_err` regret in log10
(lower is better), with failing actions offered and charged:

| chooser | regret | pick-failure rate |
|---|---:|---:|
| `spend_budget` *(not deployable — see below)* | 0.2253 | 0.0 % |
| **`advisor_gated_0.05`** | **0.3468** | 10.0 % |
| `advisor_argmin` | 0.4413 | 22.7 % |
| `finest_action` | 0.4462 | 3.3 % |
| `default` | 0.5186 | 0.0 % |
| `constant_config` | 0.5275 | 18.3 % |
| `advisor_policy` | 0.5601 | 21.3 % |
| `random` | 0.5375 | 33.3 % |

Paired sign tests, pooled over 6 folds × 5 seeds:

- `advisor_gated_0.05` vs `advisor_argmin`: **38W-0L-262T, p = 7.3e-12** — the
  gate never makes a case worse, it only ever fixes one.
- vs `finest_action`: 155W-98L-47T, p = 4.1e-04.
- vs `constant_config`: 168W-70L-62T, p = 1.8e-10.
- vs `default`: 186W-108L-6T, p = 6.3e-06.
- `advisor_argmin` vs `finest_action`: 117W-136L-47T, p = 0.258 — **ranking
  alone does not beat the trivial rule.** The gate is what earns the win.

`spend_budget` (pick the most expensive feasible action) beats everything, but
it is **not a deployable baseline**: it ranks by *measured* DOF, so it can never
select an action that failed, which shows up as an impossible 0.0 % pick-failure
rate at every budget. It has hindsight. `finest_action` is the honest form of
the same idea and is the comparator any claim should use.

## What the model has and has not learned

Holding cost nearly constant (a narrow DOF band, so only judgement separates the
choosers), the advisor is the **worst** chooser measured, below random, with the
shipped `default` best:

| chooser | band 0.4–0.6 | band 0.7–0.9 |
|---|---:|---:|
| `default` | **0.1305** | **0.1705** |
| `finest_action` | 0.1865 | 0.2066 |
| `constant_config` | 0.1864 | 0.2773 |
| `random` | 0.2785 | 0.3330 |
| `advisor_argmin` | 0.3013 | 0.3422 |

**The advisor's win comes from spend allocation and feasibility filtering, not
from per-case judgement about which action to buy at a given price.** That is a
precise, falsifiable claim about the model's competence and it should be quoted
in preference to any headline ratio.

## Uncertainty, calibration and abstention

- **The feasibility head is miscalibrated.** Mean ECE 0.4795, Brier 0.4721
  against a base failure rate of 0.381. This is invisible in the `failure_auc`
  of ~0.98 historically reported, because AUC is threshold-free.
- **The shipped 0.5 veto is not a safety mechanism.** It abstains on 44.8 % of
  queries while still letting 22.1 % of failures through. Holding missed
  failures under 2 % requires a 0.95 threshold and abstention on 78.5 %.
- **Split-conformal intervals do not hold across families.** Nominal 90 %
  coverage achieves 24.6 %. That is not a defect in the method: conformal
  guarantees coverage only under exchangeability, which leave-one-family-out
  deliberately breaks, so the gap is a *measurement* of the shift.
  Group-conformal restores coverage (84.6 % at nominal 90 %) but only with a
  ±10-decade band, i.e. an honest interval on an unseen family says nothing.
- **The OOD gate is distance-based and validated.** Mahalanobis distance over
  the 41 geometry columns, shrunk covariance, threshold at the training 99th
  percentile: **100 % of held-out-family rows flagged in all 6 folds**, at a 1 %
  in-sample false-alarm rate. Parameters in `bench/advisor/ood.json`.

There is an irony worth stating: the 15 offline CAD descriptors *hurt* held-out
regret, because a 1-NN classifier recovers the family from them alone at 32/32 —
on a narrow corpus they are family identifiers rather than transferable physics.
The same property makes them close to ideal for OOD detection, which is what
they are now used for.

## Known failure modes

- **Extrapolation on an unseen family is catastrophic, not graceful.** Held-out
  residuals by family: `box_hole` 0.30, `plate_notch` 0.42, `l_bracket` 0.75,
  `sphere_box` 2.50, **`stepped_shaft` 11.05 decades**. More training makes it
  worse (15.8 → 32.3 → 20.0 decades at 25/100/300 epochs), so it is a per-family
  cliff, not undertraining. Regret survived it because regret depends only on
  the argmin and a ranking tolerates a large constant offset.
- Consequently `predicted_rel_err` / `predicted_dof` must be suppressed, not
  printed, when the OOD gate fires. The M-A1 log records a `predicted_dof` of
  1.5e15 on an unseen part.
- Two of the six action dials mostly do not do what their names suggest: in
  59 % of 834 matched pairs, `adapt_passes = 1` changes no element count at all
  (DOF 3,396 → 21,345 with `n_elems` fixed at 4,332 — that is tet4 → tet10).
  The adaptive path is largely elevating order, not refining locally.

## Reproducibility

Every checkpoint and every report artifact carries a `provenance` block: git
revision (suffixed `-dirty` when the tree is uncommitted), dataset path and
SHA-256, row count, split mode and fold, held-out groups, input/action widths,
the geometry-descriptor list and its SHA-256, seed, and Python/NumPy/Torch
versions. Inference is single-threaded with a fixed graph.

## Evaluation harness

`scripts/advisor/regret.py` (choosers, budget-constrained regret, sign tests),
`crossval.py` (folds × seeds), `calibration.py` (reliability, conformal, OOD),
`learning_curve.py` (regret vs corpus width), `evaluate.py` (single checkpoint).
`evaluate.py` and `crossval.py` share the scoring module so they cannot report
different things.
